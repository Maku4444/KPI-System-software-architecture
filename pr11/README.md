# Fault-Tolerant Multithreading (Відновлення після SIGSEGV)

### Опис завдання
Розробка багатопоточної програми, яка виконує критичні обчислення і здатна "вижити" після отримання сигналу SIGSEGV (Помилка сегментації), відновивши свою роботу з останньої збереженої контрольної точки (Checkpoint).

### Архітектура рішення
1. Thread-Local Storage (TLS): Використано ключове слово __thread для змінних стану. Це гарантує, що пам'ять контрольних точок ізольована для кожного потоку.
2. `sigsetjmp` / `siglongjmp`: Використано для реалізації нелокального переходу (non-local goto). sigsetjmp створює "знімок" процесора, а siglongjmp у обробнику сигналу повертає виконання в цю точку, відновлюючи маску сигналів.
3. `volatile`: Змінні стану обчислень оголошені як volatile, щоб компілятор не оптимізував їх у регістри, що могло б призвести до їх обнулення після нелокального переходу.

### Результат
На скриншоті зафіксовано симуляцію збою у Потоці №1. Обробник перехопив SIGSEGV, запобіг завершенню всього процесу та успішно відновив роботу потоку зі збереженим проміжним результатом, при цьому Потік №2 навіть не помітив збою.
