# Варіант 5: Симуляція збою `write()` та атомарний запис

### Опис завдання
Програма демонструє проблему часткового (пошкодженого) запису під час апаратного або програмного збою та реалізує архітектурний патерн **Atomic Write** (Атомарний запис) для збереження цілісності даних.

### Архітектурне рішення
Замість прямого запису в оригінальний файл, програма:
1. Створює тимчасовий файл (`.tmp`).
2. Виконує системний виклик `write()` та скидає кеш на диск через `fsync()`.
3. Використовує системний виклик `rename()` для атомарної підміни старого файлу новим.
Якщо стається збій посеред запису (симулюється в коді), оригінальний файл залишається неушкодженим.
