# Варіант 5: Моделювання ситуації «Write-Only» (Тільки для запису)

### Опис завдання
Демонстрація сценарію, коли користувач має права на запис до файлу, але не може його прочитати (права доступу `--w-------` або `200`).

### Наслідки для безпеки та роботи програм
Цей механізм (відомий як "Drop-box" або "сліпий запис") часто використовується для файлів аудиту (логів), куди програми можуть лише додавати інформацію, але не можуть читати записи інших. 
Однак, без спеціального атрибуту "тільки дописування" (append-only), користувач із правами `write-only` може випадково або навмисно обнулити файл чи перезаписати його вміст, не знаючи, що там було раніше. Редактори (наприклад, `nano`) не зможуть працювати з таким файлом, оскільки їм потрібне початкове читання для виводу інтерфейсу.

### Результат виконання
На скриншоті показано, як системний виклик `open(O_RDONLY)` отримує жорстку відмову `Permission denied`, тоді як наступний виклик `open(O_WRONLY | O_APPEND)` успішно записує дані у файл.
